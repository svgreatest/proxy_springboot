Strict Trust Anchor Isolation Rules

1. Ephemeral In-Memory First: Candidate CAs are injected only into a cloned in-memory BCFKS store during probe.

2. Zero Persistent Touches on Failure: If the connection fails for any reason, the disk keystore remains 100% untouched.

3. Only Required Anchors Committed: If a candidate CA was provided but the connection was validated by an existing system anchor, commit is blocked to prevent keystore pollution.
